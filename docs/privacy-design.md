# ClassCare 班級轉銜與學生理解工作台 — 隱私設計與資料防護 (Privacy by Design)

本系統儲存學生的學習支持摘要、家庭聯絡與敏感行政警示，隱私防護與資料最小化為本專案最高優先原則。

> [!NOTE]
> **當前狀態**：
> *   設計規範：`DOCUMENTED` (已編寫文件)
> *   系統對應檔案及資料庫：`IMPLEMENTED` (後端資料遮罩與唯讀服務已實作，尚未在 GAS 真實環境驗證)

---

## 1. 資料最小化與脫敏原則 (Data Minimization & Masking)
*   **不收集不必要之識別碼**：學生、家長檔案一律不登記身分證統一編號或戶照號碼。
*   **電話號碼遮罩處理**：前端工作台一律不回傳與不呈現完整電話號碼。所有家長電話必須通過後端 `PrivacyService.maskPhone()` 進行掩碼處理（例如：`0912***678`），保護家庭聯絡隱私。
*   **附件連結隔離隔離**：`restricted_document_url`（如健康診斷書與低收證明 Drive 連結）僅留存在後端資料庫做簽審存檔。**任何導師工作台 API 與 payload 一律不回傳 restricted_document_url**，防範機密附件外流。
*   **健康與行政行動化摘要**：導師僅需知道「如何預防與第一時間處置」，因此 `health_alerts` 僅保留對應的行動方針，不記錄學生的完整醫療診斷書或詳細病史。
*   **排除負面標籤**：親師聯絡紀錄與支持摘要應描述具體客觀行為，禁止設定家長評等、家庭功能分數或心理狀態負面文字（如「功能不全家庭」、「過動傾向」等非醫療診斷文字）。

---

## 2. 存取留痕與稽核日誌 (Audit Logging)
為了防止內部人員不當調閱資料，本系統在讀取特定資料時執行自動稽核：
*   **觸發模組**：
    *   開啟學生詳細資料頁面。
    *   讀取個別學生家庭聯絡方式（電話、地址）。
    *   讀取健康行動提醒摘要 (`health_alerts`)。
    *   讀取補助申請與行政提醒紀錄 (`subsidy_records`)。
*   **日誌儲存**：存入 `access_logs` 工作表，包括時間、帳號、存取模組、受影響學生 ID。
*   **使用者識別之根**：所有日誌所記錄的 `user_email` 一律經由後端 `Session.getActiveUser().getEmail()` 直接獲取，不採用前端傳遞的參數值，防止日誌被偽造與規避。
*   **日誌脫敏**：日誌本身僅記錄「執行了讀取動作」，絕對不把讀出的內容（例如學生的病情、補助款金額、家長電話）作為 metadata 寫入日誌，以避免二次洩漏。

---

## 3. 前端零敏感快取政策 (Client-side Security)
*   **LocalStorage 限制**：嚴禁在瀏覽器的 `localStorage` 或 `sessionStorage` 儲存學生姓名、輔導紀錄、身心狀況或聯絡電話。所有資料皆需在關閉瀏覽器分頁時自動清除，切換學生時應確保清除 DOM 快取。
*   **Console 脫敏**：程式碼中嚴禁使用 `console.log` 輸出任何包含學生隱私的物件或字串。
*   **URL 脫敏**：所有的路由與搜尋功能一律不將學生姓名、身心警示或電話放入網址參數 (Query string) 中。

---

## 4. 拒絕「直接傳回整張表」
*   後端服務層禁止設計諸如 `getAllStudents()`、`getAllHealthAlerts()` 這類將整張試算表讀取後打包回傳給前端的函式。
*   所有的查詢都必須經過後端 `PermissionService` 的 `validateClassAccess` 或 `validateStudentAccess` 過濾，只回報經過 `PrivacyService` 處理過的單筆或經授權的陣列子集。
